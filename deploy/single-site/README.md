# Enterprise E1 Single-Site Deployment Foundation

Status: E1-M1 implementation slice. This is a versioned, non-development, single-trusted-site
foundation using local admin-token identity and SQLite. It is not production identity, runtime
PostgreSQL, high availability, hosted operation, production readiness, or human UAT evidence.

The supported E1-M1 topology is one Gateway API container and one Command Center UI container on
explicit loopback ports. The optional Ithildin Node is intentionally not part of this first
deployment checkpoint; its signed configuration, continuity, and recovery topology enter through
E1-M2 and E1-M3. Ithildin does not receive Docker lifecycle authority. The operator invokes the
fixed Compose commands below.

## 1. Prepare the owner-only environment

Copy `deploy/single-site/env.example` to an absolute path outside the repository. Replace every
placeholder, then set mode `0600`. The file is the supported secret location for the local admin
token; do not commit it, pass the token as a command argument, or print it in evidence.

Set:

- one lowercase site identifier;
- one semantic deployment version;
- the exact clean Git commit being built;
- distinct unprivileged loopback API and UI ports;
- an absolute data root outside the source tree;
- an absolute, read-only (`0400` or `0444`) owner-controlled runtime-candidate inventory;
- an absolute, read-only (`0400` or `0444`) owner-controlled detached authorization record for that
  inventory;
- the expected runtime posture, exactly `reviewed` or `unreviewed_local`; and
- container UID/GID equal to the operator UID/GID that owns the data root.

The API's stdlib bootstrap revalidates the read-only runtime-candidate inventory against the image
contents and then revalidates the detached authorization before importing the application. Neither
file is generated by bootstrap or Compose. That binding is candidate identity evidence only; it
does not authorize release, promotion, production, or UAT.

Use `reviewed` only when both records were produced for the exact source candidate by the separate
candidate-review workflow. For an engineering rehearsal before that workflow, use
`unreviewed_local` with explicit read-only empty-object sentinel files. The authenticated health
probe then requires the Gateway to report `unreviewed_local`; these sentinels are evidence of
unavailability, not reviewed-candidate evidence.

## 2. Bootstrap and validate state

The bootstrap creates only these exact directories with mode `0700`, refusing symlinks, unexpected
file types, unsafe modes, wrong ownership, source-tree placement, broad roots, duplicate ports,
placeholder/dev tokens, and source-revision mismatch:

```text
<data-root>/
  gateway/
    db/
    keys/
    logs/
    signatures/
  workspaces/
```

Run:

```sh
make enterprise-e1-single-site-bootstrap E1_ENV_FILE=/absolute/path/ithildin-e1.env
make enterprise-e1-single-site-config E1_ENV_FILE=/absolute/path/ithildin-e1.env
```

`bootstrap` never starts Docker. `config` reruns the preflight before asking Compose to render the
fixed profile.

## 3. Build, start, and verify

```sh
make enterprise-e1-single-site-up E1_ENV_FILE=/absolute/path/ithildin-e1.env
make enterprise-e1-single-site-health E1_ENV_FILE=/absolute/path/ithildin-e1.env
```

The versioned API and UI image tags and OCI labels bind the operator-selected version to the exact
source revision. Both host bindings remain on `127.0.0.1`. The Gateway receives only read-only
configuration mounts, the exact runtime inventory and authorization records, the owned Gateway
state root, and the owned workspace root. It receives no Docker socket, host process namespace,
broad host filesystem, arbitrary network allowlist, runtime PostgreSQL, or hosted telemetry
configuration.

The bounded health command probes the configured loopback API `/healthz`, authenticated
`/system/status`, and Command Center root. It requires exactly 24 governed tools, SQLite, and the
operator-declared runtime-candidate posture. API health proves Gateway HTTP readiness only. UI
reachability proves Command Center HTTP reachability only. Neither proves Node connectivity,
runner health, model-provider state or success, production readiness, or end-to-end mission
success.

## 4. Shutdown and ownership

```sh
make enterprise-e1-single-site-down E1_ENV_FILE=/absolute/path/ithildin-e1.env
```

Shutdown stops and removes only the fixed site Compose project. It does not delete the owner-held
data root, workspaces, keys, audit log, database, runtime authorization, images, or source checkout.
The operator owns backup, retention, image removal, credential rotation, and recovery decisions.
Do not delete or overwrite state when ownership or candidate identity is ambiguous.

## Validation

```sh
make enterprise-e1-single-site-deployment-check
make enterprise-e1-milestone-check
```

The first command is static and test-only; it does not contact Docker or a network service. The
milestone checkpoint preserves the inherited Local v1 contract, the descendant-safe PIS
external-input wait, exactly 24 governed tools, and the no-new-powers guardrail.

On an engineering host with Docker available, the isolated observed rehearsal is:

```sh
make enterprise-e1-single-site-rehearsal
```

It requires a clean checkout, generates a unique version and project, builds both images, verifies
their exact OCI revision/version labels, authenticates the 24-tool status probe, shuts down only
that project, observes state after shutdown, removes the unique images and synthetic private
state, and retains one secret-free report under ignored `var/enterprise-e1-single-site/`. It
deliberately runs in `unreviewed_local` posture until E1-M6 supplies separately reviewed evidence.
